How it was run

  • Failed attempts are mostly retries. Python and Node run as one process. While it is busy answering requests, it accepts new connections slowly, so waiting connections get reset. The test tool retries each one straight away, and every retry counts as another failure.
  • Go used about 3.3 CPU cores with no setup. Python and Node each used one core, which explains most of the gap. Running them with several worker processes would narrow it.
  • The test tool ran on the same Mac and competed with the servers for CPU, so Go's figure is probably limited by the machine.
  • Each backend got 5 seconds of warm-up traffic first, which isn't counted. Requests still in flight at 30 seconds were allowed to finish.
